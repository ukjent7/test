# 实现前确定的失败场景

端到端验证经过真实 HTTP 上游、Rust 网关进程和客户端，禁止用适配函数的单元测试替代。

1. 日志中的 `thinking` 起始块缺少 `signature`，Grok 的必填字段反序列化失败。
2. 起始签名为 null，或 thinking 文本未初始化；应采用 pi 的空字符串默认值。
3. 已有签名、分段 signature_delta、多 thinking 块、redacted_thinking 被修改或丢失。
4. SSE 跨 HTTP 分片，分片落在中文 UTF-8 字符、JSON 或 CRLF 分隔符中；事件不能损坏。
5. SSE 包含多行 data、注释、id、retry、ping；修补应保留这些字段与事件顺序。
6. 非流式响应或 message_start 内已有 thinking 内容也缺少 signature。
7. 无签名思考内容被 Grok 回传为 thinking 块；按 pi 默认策略转为 text，已有签名和 redacted_thinking 原样回传。
8. 空的无签名 thinking 需移除，但不能移除同消息中的工具调用、正文；仅含空 thinking 的 assistant 消息需跳过。
9. 工具 JSON 增量、tool_result、用量和停止原因在透传中改变。
10. Authorization、x-api-key、anthropic-version、anthropic-beta、查询参数、上游路径未正确转发。
11. 修补后沿用旧 Content-Length；Connection 指定的逐跳头被错误转发。
12. 上游 401/429/500 的状态码、错误体和 Retry-After 丢失；上游重定向被自动跟随。
13. 成功响应中不合法的 JSON 被伪造成成功；SSE 中不合法的 data 被悄悄丢弃。
14. 上游流中途断开被伪造成正常结束；网关等待完整回答才发首个事件。
15. `/responses`、`/chat/completions` 意外启用，或错误消息被当成正常 message 修补。

CI 产物：脱敏的故障日志夹具、每个场景的上下游请求/响应、首事件及时性记录、Grok 实际生产 wire types 反序列化结果、汇总报告及 SHA-256 清单。失败时也上传已有证据。

## 第二版：先确定 GUI 与迁移失败场景

1. 双击程序未创建真正的桌面 WebView 窗口，或 GUI 和转发服务启动顺序导致空白页。
2. 界面显示的运行状态、地址、请求数、修补数与真实网关不一致。
3. 停止后仍发起上游请求；重新启动后不能继续修补 Messages 响应。
4. 修改上游后未立即生效；重启丢失保存的设置；无效地址覆盖可用设置。
5. 保存失败却显示成功；环境变量覆盖规则不明确。
6. 请求记录泄露 API key 或用户消息，或不记录上游错误、取消和修补数量。
7. 复制接入地址、设置对话框、键盘 Escape 或深浅主题在实际界面中失效。
8. 窄窗口内容溢出、深色模式不可读，或轮询重绘打断用户输入。
9. GUI 管理接口允许远端请求或跨站点修改上游地址。
10. edition 2024 的作用域、导入排序、resolver 或 reqwest 0.13 TLS 功能变化使原有 16 场景回归。
11. GUI 启动时端口被占用，用户只看到程序静默退出。

GUI E2E 在 CI 操作真实控件，Windows 连接实际桌面 WebView2，Linux 操作同一内嵌页面并启动原生窗口做烟测；保存浅色/深色/窄窗口截图、浏览器 trace、状态快照、设置持久化和 SHA-256 报告。原有协议 E2E 使用 `--headless`，仍穿过真实 Rust 服务。

## 请求/响应 diff：实现前确定的失败场景

1. 请求与响应修改混在一起；缺失字段、null 和空字符串显示为同一值。
2. 无签名 thinking 转为 text、删除空块或整个助手消息后，显示的前后数组索引不对应实际上下游内容；未修改的签名、工具调用被误报为修改。
3. SSE 的多个事件或多个 thinking 块无法区分；记录 diff 导致首事件等待整段响应，或中途失败丢失已有修改。
4. 未修改、上游报错或停止转发的请求显示虚假的修补；已有修补数和错误状态改变。
5. diff 中的 HTML 或脚本文本被执行；查询其他请求显示上一条记录，过期记录无提示，弹窗被后台轮询关闭或覆盖。
6. 差异泄露请求头、API key 或未修改的正文；差异写入磁盘；每秒状态轮询重复传输整份差异。
7. diff 在实际桌面窗口、深色或窄窗口中不可读，键盘 Escape 无法关闭。

E2E 穿过真实 HTTP 上游和网关，并操作 GUI 查看实际修改。产物增加 JSON/SSE diff 快照、请求前后对应证据、浅色/深色/窄窗口 diff 截图；继续验证原有协议与 GUI 场景。

## Zen 第二上游：实现前确定的失败场景

1. 两边地址不能独立设置、取消也保存，或保存/重启后地址不一致；StepFun 和自定义地址失效。
2. 用入站 Host 或 URL 子串判断 Zen，使其它域名、子域名、相近路径也触发伪装。
3. Zen 收到原客户端 User-Agent、Cookie、Forwarded、X-Forwarded-*、SDK 标识或追踪头；重复鉴权头和 Connection 指定的头穿透清洗。
4. Bearer 密钥未转换为 Messages 的 x-api-key，或已有 x-api-key 被覆盖；anthropic-version/beta 丢失；缺失版本未补默认值。
5. 会话 ID 不符合 ses_ + 12 小写十六进制 + 14 字母数字的格式，同一会话的后续请求改变 ID，合法 OpenCode 会话被重写，或不同会话混用。
6. 伪装改变 stream、tools、system、模型、查询参数或正文；Zen SSE 首事件等待完整响应，错误码被吞掉。
7. 新会话头、密钥、原始会话 ID 被记录进 UI 差异或设置文件；切回其它上游仍保留 Zen 伪装。

CI 使用本机 HTTP 代理接收以 opencode.ai 为真实目标主机的请求，不连接在线服务；保留各场景请求头/正文、响应、会话关联断言、报告和 SHA-256 清单，GUI 保存两边设置截图。测试仅使用虚构凭证；在线免费层另外通过下面的临时 Actions 探测确认。

## 模型列表与按前缀路由：实现前确定的失败场景

1. `opencode/mimo-v2.5-free` 和 `stepfun/step-5-preview` 没有分别发往两边上游，或前缀被原样发往上游；普通模型破坏现有 StepFun 接入。
2. `/v1/models` 没有真实拉取两边 `/models`，返回没有前缀或没有保留上游元数据；某边报错导致另一边的模型也不可见，全部失败却返回成功。
3. Chat/Responses 模型被错误发往 Messages，Chat/Responses 正文或响应被 thinking 修补破坏；Zen 的原生接口使用错误鉴权头。
4. 两个上游地址互相覆盖、旧设置无法迁移、停止转发失效；查询参数、HTTP 错误、JSON/SSE 行为发生回归。
5. 模型前缀修改未出现在请求 diff，响应中模型名不便关联；设置中存储的凭证通过状态接口或 E2E 产物泄露。

继续使用真实 HTTP/代理上游和真实 Rust 二进制验证，产物保存带前缀的模型列表、去前缀后的请求捕获、两边独立路径与原生 Chat/Responses 流式/非流式证据。

## 实测免费层：实现前确定的失败场景

Actions 实测 MiMo：只有头伪装、只有 stream、只有五个工具均返回 403 FreeTierError；stream + 五个工具返回 200。因此仅在 Zen Chat/Responses 明确返回 FreeTierError 后补充必要字段并重发一次，不改正常付费请求。

1. 普通 403/401/429 被自动重发；已满足免费层要求仍重复发送；重发使用了新设置或新会话。
2. 补工具覆盖客户已有工具/参数/选择，非工具客户端意外收到占位工具调用。
3. 客户要求非流式却收到 SSE，合并时丢失内容、reasoning、签名/工具参数增量、usage、停止原因或多 choice；缺失结束事件、坏 JSON 或中途断开被伪造成成功。
4. 客户原本要求流式却被整段缓冲；合并误应用到正常付费请求；改写没有记录 diff，或记录完整未修改正文。

本地上游夹具重现免费层拒绝条件，保留首次拒绝、补形态后的请求、客户端 JSON/SSE 与校验清单；线上诊断证据单独保存，网络限制不混入确定性回归测试。

## 缓存亲和与观测：实现前确定的失败场景

1. Grok 的 conv ID 或 pi 的 session-id / session_id 被忽略；历史压缩后身份改变，相同首句的不同会话被合并。
2. Responses 旁路的临时 conv ID 覆盖显式 prompt_cache_key；独立旁路被父会话 ID 合并；每次变化的请求 ID 改变路由。
3. 空标识阻止后续有效标识；合法 OpenCode 会话或原有亲和头的优先级改变；免费层重发改变身份。
4. Messages 把不含缓存的 input_tokens 当作总输入，Chat / Responses 又重复加缓存；累计 SSE usage 被累加，后续 delta 丢失先前字段。
5. 缓存字段缺失被当成零命中；明确为零时反而显示未报告；DeepSeek 的缓存读取字段被遗漏。
6. 观测改变原生 JSON/SSE 字节、逐事件转发、UTF-8 分片、多行 data、尾事件或已有 thinking 修补；错误响应伪造缓存用量。
7. 状态或差异暴露原始会话、缓存键、凭证或未修改正文；指纹不稳定，或记录了错误的身份来源；重启仍保留观测记录。
8. GUI 不展示输入/缓存读写和身份来源，零与未报告无法区分，深浅主题与窄窗口溢出。

HTTP E2E 捕获主请求 → 独立旁路 → 主请求及共享缓存旁路，验证实际转发身份；三种协议的 JSON/SSE 使用已知用量夹具，证明口径正确且响应不变。GUI E2E 保存缓存记录、浅色/深色/窄窗口截图与浏览器 trace。所有证据纳入现有 report.json 与 SHA-256 清单；夹具验证不会冒充真实上游缓存命中实验。
